# Re-ID: распознавание и устойчивая идентификация людей

Документ описывает, **как работает Re-ID** (re-identification — повторное опознание
личности) в проекте: какие сигналы используются, как кадр превращается в стабильное
имя человека, как устроена память (галерея), как она стареет и сохраняется на диск,
и какие параметры на что влияют.

> TL;DR. Каждый человек в кадре получает устойчивый `global_id`. Основной сигнал —
> **лицо** (InsightFace), вторичный — **внешний вид/одежда** (Body Re-ID, опознание
> «со спины»). Память о людях хранится в `data/face_gallery.pkl`, накапливает разные
> ракурсы, со временем затухает (TTL) и переживает перезапуск.

---

## 1. Зачем это нужно

Детектор (YOLO) + трекер (ByteTrack) дают **`track_id`** — номер объекта в пределах
одной непрерывной траектории. Но `track_id` теряется, как только человек вышел из
кадра, был перекрыт или повернулся так, что трекер потерял его на несколько кадров.
После этого тот же человек получает **новый** `track_id`.

Re-ID решает эту проблему: связывает разные `track_id` (в т.ч. с разных камер) с
одной устойчивой личностью — **`global_id`** — и присваивает ей имя. Это нужно для:
- стабильных имён на стриме (не «Гость_1 → Гость_2 → …» каждые пару секунд);
- пропусков по жесту ОК (пропуск привязан к личности, а не к треку);
- кросс-камерной идентичности;
- управления галереей оператором (`GalleryModal`).

## 2. Архитектура: два сигнала

| Сигнал | Модуль | Когда работает | Стойкость |
|---|---|---|---|
| **Лицо** | `backend/reid/recognizer.py` (InsightFace `buffalo_l`) | видно фронтальное лицо | биометрия, долговечно |
| **Тело / внешний вид** | `backend/reid/body.py` (OSNet или цвет) | человек спиной/боком | завязано на одежду, недолговечно |

Решение по лицу — **главное**. Body Re-ID — **вспомогательное**, используется
консервативно: только **восстанавливает** личность для трека без лица и без уже
назначенной личности; решение по лицу он **никогда не перекрывает**.

Память обоих сигналов хранится в одной галерее (`FaceGallery`,
`backend/reid/gallery.py`), персистится в `data/face_gallery.pkl`.

Управляется всё одним тумблером режима детекции **`faces`** (`DETECT_MODES`).

---

## 3. Поток обработки одного кадра

```
CameraCapture ─→ FrameBuffer ─┬─→ FaceRecognitionWorker (свой поток на камеру)
   (raw-кадр)                 │     детектит лица каждый REID_FRAME_SKIP кадр,
                              │     кеширует _latest_faces
                              │
                              └─→ _camera_detection_worker (поток детекции)
                                    └─→ process_frame():
                                         1. run_detection (YOLO+ByteTrack) → persons + track_id
                                         2. face_worker.get_faces() → лица (кеш)
                                         3. match_faces_to_persons → лицо ↔ человек
                                         4. body_recognizer.extract_batch(clean_frame) → дескрипторы тел
                                         5. на каждого человека:
                                            state.get_global_id(track_id, cam, face_emb, quality,
                                                                 person_box, body_emb) → global_id
                                         6. имя, СИЗ, зоны, жесты, отрисовка
```

Ключевые моменты:
- **Лица детектятся в отдельном потоке** (`FaceRecognitionWorker`), а не в потоке
  детекции — чтобы тяжёлый InsightFace не блокировал YOLO. Поток детекции читает
  **готовый кеш** лиц (`get_faces()`), который может отставать на несколько кадров.
  Это нормально: личность устойчива, кадровая точность лица не критична.
- **Один `FaceRecognizer` (InsightFace) на все камеры**, доступ к сессии
  сериализован локом (`_infer_lock`) — `app.get()` потокобезопасен.
- **Дескриптор тела берётся с «чистого кадра»** (`clean_frame` — копия до отрисовки
  рамок/заливки зон), иначе оверлеи исказили бы внешний вид.
- **Body extract — батчем**: `extract_batch` для OSNet даёт **один инференс на кадр**
  (кропы людей пачками по 16), а не один на человека.

## 4. Лицевой Re-ID (`recognizer.py`)

### 4.1. `FaceRecognizer.detect_faces(frame)`
InsightFace `buffalo_l`, провайдеры CUDA→CPU, 3 попытки загрузки (чистит пустую папку
модели и докачивает; при SSL-ошибке печатает инструкцию ручной установки).

Возвращает список `(bbox, embedding, quality)`:
- **`embedding`** — 512-мерный, **L2-нормированный** (для косинуса).
- **`quality`** = `det_score*0.7 + size_score*0.3`, где `size_score` растёт с долей
  лица в кадре (насыщается при ~10% ширины/высоты). Клампится в **[0.35, 1.0]**.
  Качество управляет адаптивным порогом и троттлингом хранения (см. ниже).

### 4.2. `FaceRecognitionWorker`
Поток на камеру. Детектит лица каждый **`REID_FRAME_SKIP`** (3) кадр, кеширует в
`_latest_faces`. Стартует/останавливается по флагу `DETECT_MODES["faces"]`
(`start_face_workers`/`stop_face_workers`).

### 4.3. `match_faces_to_persons(person_boxes, face_data)`
Сопоставляет лица людям: для каждого человека ищет лицо с максимальным **overlap**
(площадь пересечения / площадь лица), при равенстве — по близости центров. Возвращает
для каждого человека `(лучший_эмбеддинг, качество)` или `(None, 0.0)`.

## 5. Галерея (`gallery.py::FaceGallery`)

Потокобезопасное (`threading.Lock`) pickle-хранилище. Структура записи личности:

```python
gallery[global_id] = {
    'embeddings':      [np.ndarray, ...],   # ракурсы ЛИЦА (512d, L2-норм)
    'embedding_ts':    [float, ...],        # таймстамп добавления каждого лица
    'body_embeddings': [np.ndarray, ...],   # ракурсы ТЕЛА (512d OSNet / 256d цвет)
    'body_ts':         [float, ...],        # таймстамп добавления каждого тела
    'last_seen':       float,               # когда личность видели в последний раз
    'cameras':         {cam_id, ...},       # на каких камерах встречалась
    'name':            str,                 # имя (Гость_N или заданное оператором)
}
```

### 5.1. Адаптивный порог `_adaptive_threshold(quality)`
Чем лучше качество лица — тем мягче порог совпадения (хорошему лицу строгость не
нужна):

| Качество | Порог косинуса |
|---|---|
| ≥ 0.8 (отл) | 0.45 |
| ≥ 0.6 (хор) | 0.50 |
| ≥ 0.4 (ср) | 0.55 |
| < 0.4 (плох) | 0.60 |

Дополнительно при матче порог снижается для «обжитых» записей: −0.08 при ≥2
эмбеддингах, ещё −0.05 при ≥5 (чем больше ракурсов накоплено, тем увереннее матч).

### 5.2. «Запоминание со всех сторон» + защита якоря
- До **`REID_MAX_EMBEDDINGS`** (30) ракурсов лица на личность.
- **Якорь** — первый (эталонный) эмбеддинг (индекс 0) — **неприкосновенен**.
- При переполнении вытесняется **самый старый по времени** НЕ-якорный эмбеддинг
  (по `embedding_ts`), а не вслепую.

### 5.3. Diversity-гейт
Новый ракурс добавляется (в «липком» пути), только если он достаточно **отличается**
от уже сохранённых: max косинус к ним < **`REID_DIVERSITY_MAX_SIM`** (0.92). Так 30
слотов покрывают реальные повороты головы, а не 30 почти-одинаковых кадров.

### 5.4. Затухание памяти лиц по времени (TTL)
- У каждого эмбеддинга есть `embedding_ts`.
- `prune_old_embeddings(max_age_days)` стирает ракурсы старше
  **`REID_EMB_MAX_AGE_DAYS`** (env, дефолт **30 дней**), **сохраняя якорь**: образ
  человека остаётся в памяти, выцветают только лишние детали.
- Запускается при старте и периодически в `_heartbeat_loop` (раз в
  **`REID_EMB_CLEAN_INTERVAL`**, дефолт 3600с). `0`/отрицательное — выключено.
- Это **отдельный механизм** от удаления целых личностей (`cleanup_old`,
  `REID_MAX_AGE_DAYS`=0 → личности хранятся «навсегда»).

### 5.5. `match_or_register(embedding, cam, quality, store)`
Главная точка лицевого матча:
1. Перебирает все личности, считает max косинус эмбеддинга к их ракурсам, применяет
   персональный порог (адаптивный − бонусы за обжитость).
2. Если кто-то прошёл — обновляет `last_seen`/`cameras`, при `store` дописывает ракурс
   (с защитой якоря) → возвращает его `global_id`.
3. Иначе **регистрирует нового** «Гость_N» и сохраняет на диск.

Прочее: `merge_entries` (слияние дубликатов, синхронно режет эмбеддинги и
таймстампы), `rename`, `delete`, `clear`, `cleanup_old`.

## 6. Сердце стабильности: `state.get_global_id(...)`

`backend/core/state.py`. Связывает `track_id` с `global_id`. Здесь лечится
исторический баг «имена постоянно слетали на Гость_N». Вызывается под
`_reid_lock` (сериализует Re-ID между камерами для консистентности).

Хранит:
- `_track_to_global: {(cam, track_id) → global_id}` — текущая привязка трека;
- `_track_last_seen`, `_last_emb_store`, `_last_body_store` — таймстампы троттлинга.

### Логика по веткам

**Есть лицо** (`face_embedding is not None`):
1. **Троттлинг хранения** — ракурс добавляется в галерею не чаще
   **`REID_STORE_INTERVAL`** (1.5с) с одного трека и только при качестве ≥
   **`REID_MIN_STORE_QUALITY`** (0.55). Иначе кеш детектора лиц (один и тот же кадр)
   вытеснял бы эталоны.
2. **«Липкость»** — если у трека уже есть личность и новое лицо её **подтверждает по
   мягкому порогу** (`threshold_for(q) − REID_STICKY_MARGIN`, но не ниже
   `REID_STICKY_MIN`=0.28) — **не пересматчиваем**. Большой margin (0.25) удерживает
   личность за треком даже на слабо похожем ракурсе одного человека (sim 0.3–0.5), а
   разные люди (~0) переключаются. Лечит «постоянную перезапись» имён.
3. Иначе — `match_or_register`. При смене `global_id` аккуратно **переносит
   fallback-имя** или **сливает** старую запись (если она почти пустая), чтобы имя не
   потерялось.
4. Пока лицо видно — **запоминает тело** (`_store_body`).

**Лица нет, но у трека уже есть личность:** держим её, продолжаем запоминать тело.

**Лица нет и личность у трека неизвестна:** пытаемся **опознать «со спины» по телу**
(`match_body`). Не присваиваем личность, **активную на другом треке** в этот момент
(`_gid_active_on_other_track`) — чтобы два разных человека в похожей одежде не слились.

Возвращает `0`, если опознать никак не удалось (человек спиной, тела нет/не совпало).

## 7. Body Re-ID — опознание «со спины» (`body.py`)

### 7.1. Что это
Дескриптор **внешнего вида** (одежда + силуэт), одинаковый с лица и со спины,
L2-нормированный → сравнение косинусом. Это **не биометрия**: завязан на одежду.

### 7.2. Два бэкенда (выбор авто в `__init__`)
- **DEEP (основной)** — OSNet (`osnet_x0_25_msmt17`, ONNX, onnxruntime, CUDA→CPU).
  512-мерный семантический дескриптор, устойчивый к ракурсу. Вход 128×256, RGB,
  ImageNet-норма. Модель экспортирована со **статическим батчем 16** → `extract_batch`
  гоняет кропы пачками (один инференс на кадр). Модель (~0.9 МБ) в `models/osnet/`,
  идемпотентная докачка `body_models.ensure_body_model`; `REID_BODY_OFFLINE=1`
  запрещает сеть (тесты).
- **COLOR (fallback)** — HSV-гистограммы торса/ног (256-d), без внешних зависимостей.
  Включается мягкой деградацией, если OSNet/onnxruntime недоступны.

Дескрипторы **разной размерности не смешиваются**: `_body_sims` сравнивает только
векторы одинаковой длины (после смены бэкенда старые просто игнорируются и вытесняются
по капу).

### 7.3. Пороги под бэкенд
`BodyRecognizer.{backend, match_threshold, diversity_max_sim}` → `state.configure_body()`
(вызывается из `main.py` после инициализации):

| | Порог матча | Diversity |
|---|---|---|
| Deep (OSNet) | `REID_BODY_MATCH_THRESHOLD` = 0.60 | 0.90 |
| Color | `REID_BODY_MATCH_THRESHOLD_COLOR` = 0.82 | 0.97 |

### 7.4. Жизненный цикл (одинаков для обоих бэкендов)
- **Пока лицо видно** — тело личности **запоминается** (`_store_body`, троттлинг
  `REID_BODY_STORE_INTERVAL`=1с, diversity-гейт, до `REID_BODY_MAX_EMBEDDINGS`=12
  ракурсов).
- **Лица нет и трек новый** — личность **восстанавливается** через `match_body`.
- Консервативно: только восстанавливает, не перекрывает лицо, не крадёт личность,
  активную на другом треке.

### 7.5. Персистентность и TTL тела
- У дескрипторов тела есть таймстампы (`body_ts`) и они **сохраняются на диск** —
  узнавание «со спины» переживает перезапуск.
- TTL **короткий** — **`REID_BODY_MAX_AGE_DAYS`** (env, дефолт **2 дня**) и **без
  защиты якоря** (одежда устаревает быстро): `prune_old_bodies` стирает все
  дескрипторы старше TTL. Устарели все → личность не опознаётся со спины, пока её
  снова не увидят в лицо.
- Старые pickle без `body_ts` дозаполняются `last_seen` при загрузке.

> **Граница возможностей.** «Со спины» узнаёт, только если: (1) человека ранее в этой
> памяти видели в лицо; (2) он в той же одежде; (3) сходство выше порога. Переоделся
> или прошло >2 дней — создастся новый «Гость», пока снова не покажет лицо.

## 8. Персистентность галереи на диск

`data/face_gallery.pkl`. Запись на диск дорогая (весь pickle целиком), поэтому она
**не делается на каждый кадр**:

- **Сразу пишут** (`_save()`): регистрация нового человека, merge, rename, delete,
  clear, удаление по TTL (`cleanup_old`/`prune_*`).
- **Не пишут сразу, ставят грязный флаг `_dirty`**: «липкое» дописывание лиц
  (`add_observation`), повторный матч известного лица, добавление тела (`add_body`) —
  то есть всё «выученное за сессию».
- **`flush()`** сбрасывает на диск накопленное, **только если `_dirty`**:
  - периодически в `_heartbeat_loop` — раз в **`REID_FLUSH_INTERVAL`** (env, 30с);
  - **гарантированно при `stop_live`**.

> Замечание: `_heartbeat_loop` итерируется раз в `MQTT_HEARTBEAT_INTERVAL` (30с),
> поэтому фактический период флаша ограничен снизу этими 30с. Сохранность данных это
> не затрагивает — `stop_live` делает гарантированный флаш.

**Обратная совместимость:** старые pickle без `embedding_ts`/`body_ts` при загрузке
дозаполняются `last_seen` (нетаймстампленные считаются самыми старыми).

## 9. Имена личностей

Приоритет в `get_person_name(global_id, …)`:
1. **имя из галереи** (`name`), если оно не «ID…»;
2. иначе `#<global_id % 1000>`.

Новые личности получают **`Гость_N`**. Оператор может переименовать
(`POST /api/reid/persons/<id>/rename`), удалить, слить — см. API ниже. При смене
`global_id` логика `get_global_id` сливает почти пустые записи в целевую личность,
чтобы заданное оператором имя не потерялось.

---

## 10. Жизненный цикл треков

- `_track_last_seen` обновляется на каждом обращении к треку.
- `cleanup_stale_tracks()` (вызывается из `process_frame`) удаляет привязки треков
  старше **`TRACK_EXPIRY`** (60с) вместе с их троттлинг-таймстампами.
- `clear_tracks()` — при `start_live` (новая сессия начинается с чистого маппинга
  треков; сама галерея личностей при этом сохраняется).

## 11. Справочник параметров (`backend/config.py`)

### Лицо
| Параметр | Дефолт | Назначение |
|---|---|---|
| `REID_SIM_THRESHOLD` | 0.55 | базовый порог (адаптивный 0.45–0.60) |
| `REID_MAX_EMBEDDINGS` | 30 | ракурсов лица на личность |
| `REID_DIVERSITY_MAX_SIM` | 0.92 | копим разные ракурсы, не дубли |
| `REID_MIN_STORE_QUALITY` | 0.55 | мин. качество для записи ракурса |
| `REID_STORE_INTERVAL` | 1.5с | троттлинг записи ракурса с трека |
| `REID_STICKY_MARGIN` | 0.25 | удержание личности за треком |
| `REID_STICKY_MIN` | 0.28 | нижняя граница «липкого» порога |
| `REID_FRAME_SKIP` | 3 | детект лиц каждый N-й кадр |
| `REID_DET_SIZE` | (640,640) | размер детектора InsightFace |
| `REID_MAX_AGE_DAYS` | 0 | TTL целых личностей (0 = навсегда) |
| `REID_EMB_MAX_AGE_DAYS` | 30 | **TTL на ракурс лица** (env, 0 = выкл) |
| `REID_EMB_CLEAN_INTERVAL` | 3600с | период состаривания лиц (env) |

### Тело
| Параметр | Дефолт | Назначение |
|---|---|---|
| `REID_BODY_ENABLED` | True | включить Body Re-ID |
| `REID_BODY_MODEL` | osnet_x0_25_msmt17 | deep-модель |
| `REID_BODY_MATCH_THRESHOLD` | 0.60 | порог опознания со спины (deep) |
| `REID_BODY_MATCH_THRESHOLD_COLOR` | 0.82 | то же для цветового fallback |
| `REID_BODY_DIVERSITY_MAX_SIM` | 0.90 / 0.97 | diversity (deep / color) |
| `REID_BODY_MAX_EMBEDDINGS` | 12 | ракурсов тела на личность |
| `REID_BODY_STORE_INTERVAL` | 1.0с | троттлинг записи тела |
| `REID_BODY_MIN_AREA` | 4000 px² | мин. размер bbox для дескриптора |
| `REID_BODY_MAX_AGE_DAYS` | 2 | **TTL дескрипторов тела** (env, 0 = выкл) |
| `REID_BODY_OFFLINE` | — | `1` запрещает докачку OSNet (тесты) |

### Персистентность
| Параметр | Дефолт | Назначение |
|---|---|---|
| `REID_FLUSH_INTERVAL` | 30с | период флаша выученного на диск (env) |
| `REID_GALLERY_PATH` | `data/face_gallery.pkl` | файл галереи |

## 12. API управления галереей (`backend/api/reid.py`)

| Эндпоинт | Назначение |
|---|---|
| `GET /api/reid/persons` | список личностей (имя, камеры, кол-во ракурсов, `pass_seconds_left`) |

## 13. Тонкая настройка и типичные проблемы

- **«Имена слетают на Гость_N»** — обычно слабые/мелкие лица. Поднять
  `REID_STICKY_MARGIN`, проверить освещение/разрешение, убедиться что качество лиц
  даёт `quality ≥ REID_MIN_STORE_QUALITY` (иначе ракурсы не копятся).
- **«Разные люди сливаются в одного»** — слишком мягкий порог. Поднять
  `REID_BODY_MATCH_THRESHOLD` (со спины частая причина — похожая одежда) и/или
  базовый порог лица.
- **«Не узнаёт со спины»** — человека не видели в лицо в этой памяти, либо он
  переоделся, либо прошло > `REID_BODY_MAX_AGE_DAYS`. Также проверить, что bbox
  крупнее `REID_BODY_MIN_AREA` и поднялся именно **deep** бэкенд
  (лог `[ReID/body] OSNet активен …`); на цветовом fallback точность ниже.
- **На одном GPU агрегатный FPS ограничен GPU** — потоки перекрывают Python-склейку,
  но инференс на GPU сериализуется. Это норма.
- **`yolov8n-face.pt` / `FaceDetector` (`worker.py`) — не задействованы**: лица
  детектит InsightFace, файла модели в репо нет, `FaceDetector` тихо не загрузится.
